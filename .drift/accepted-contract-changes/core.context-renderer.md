contract: core.context-renderer
reason: Two changes, one decision. (1) Task context removed: predicting the relevant contracts from a prompt is structurally inexact — measured over 15 real commits it scored 10% precision / 89% recall, injected ~45 contracts where 2 were necessary (48 exist in total), never returned the exact set, cost 6-8k tokens per task, and manufactured the illusion of a complete invariant set. (2) File context expanded to the contract neighbourhood: anchored-only was 100% precise but only 67% recall (28 ssot-impacted contracts missed across those same commits, just 7/15 tasks complete), because editing a file that another contract declares as its SSOT can break that contract with no warning before the edit. File context now covers contracts anchored on the file AND contracts declaring it as an SSOT. Both halves are derived from the file, never predicted; SSOT candidate resolution reuses contract-paths, the same rule buildFileRecords and the git scope already apply.
