# drift-lock context

`drift-lock context` prints the DriftLock context an engineer or coding agent
should read before editing a file. It renders the contracts **anchored on that
file** — nothing more, nothing less.

Pull it for every file you are about to edit. This is exact by construction: the
contracts returned are the ones that actually govern the code you are changing.

> **Task mode (`--task "<prompt>"`) was removed.** Selecting contracts from a
> prompt is a prediction, and predictions cannot be exact: measured over 15 real
> commits in this repository it returned 10% precision and 89% recall — it
> injected virtually the whole contract corpus while still missing contracts that
> mattered, creating false confidence at a cost of 6–8k tokens per task. The set
> of contracts a change must respect is only well defined once you know the files
> it touches, so context is file-scoped only. Enforcement
> (`@drift-lock/eslint-plugin` and `drift-lock check`) remains the safety net.

## Usage

```bash
drift-lock context <file> [options]
```

## Options

| Option | Description | Default |
| --- | --- | --- |
| `<file>` | Target file to render context for. Required. | None |
| `--root <dir>` | Project root. | Current working directory |

## Examples

Render context for a file you are about to edit:

```bash
drift-lock context src/features/billing/actions.ts
```

Pull context for each file in the change:

```bash
drift-lock context src/features/billing/actions.ts
drift-lock context src/features/billing/pricing.ts
```

## Output

Prints the contracts anchored on the target file: contract IDs, scope, stability,
intent, declared sources of truth, and `llm.must_not_change` items.

When the file carries no contract, it says so explicitly rather than guessing:

```txt
Relevant Drift Contracts

No @drift contracts found for src/plain.ts.
```

## Error cases

A target file is required:

```bash
drift-lock context
```

prints:

```txt
error: missing required argument 'file'
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Context was rendered. |
| `1` | The command was called without a target file, config was invalid, or context extraction failed. |
