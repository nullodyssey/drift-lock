# drift-lock skills

`drift-lock skills` manages bundled DriftLock anti-drift agent skills. Use it
to list the roles shipped with the CLI or install them into an agent-specific
project layout.

The `skills` namespace has two executable subcommands:

- `drift-lock skills list`
- `drift-lock skills install`

## Usage

```bash
drift-lock skills list [--details]
drift-lock skills install [skills...] [options]
```

## Subcommands

| Command | Description |
| --- | --- |
| `drift-lock skills list [--details]` | List bundled DriftLock role skill names, or show role codes and use cases. |
| `drift-lock skills install [skills...]` | Install selected bundled skills, or all bundled skills when none are specified. |

## Options

`skills list` accepts:

| Option | Description | Default |
| --- | --- | --- |
| `--details` | Show role codes and use cases instead of names only. | `false` |

`skills install` accepts:

| Option | Description | Default |
| --- | --- | --- |
| `[skills...]` | Skill names to install. When omitted, installs all bundled skills. | All bundled skills |
| `--provider <provider>` | Target provider: `openai`, `claude`, or `cursor`. | `openai` |
| `--root <dir>` | Project root. | Current working directory |
| `--drift-command <command>` | DriftLock command prefix embedded in installed skills. | `npx --yes @drift-lock/cli` |
| `--force` | Overwrite existing installed skills. | `false` |

## Examples

List bundled skills:

```bash
drift-lock skills list
```

List bundled skills with role codes and use cases:

```bash
drift-lock skills list --details
```

Install all OpenAI-compatible skills:

```bash
drift-lock skills install --provider openai
```

Install one Claude skill:

```bash
drift-lock skills install drift-cm --provider claude
```

Install a Cursor rule with a custom DriftLock command prefix:

```bash
drift-lock skills install drift-analyst \
  --provider cursor \
  --drift-command "pnpm exec drift-lock"
```

Overwrite existing installed skills:

```bash
drift-lock skills install --provider openai --force
```

## Output

`skills list` prints one bundled skill name per line. The current bundled skill
set is:

```txt
drift-analyst
drift-architect
drift-cm
drift-dev
drift-tech-writer
drift-ux-designer
```

`skills list --details` prints role codes and use cases:

```txt
CODE  SKILL               USE CASE
CTX   drift-cm            Prepare task context and route work
DEV   drift-dev           Implement under Drift constraints
IMP   drift-analyst       Assess impact, risk, and proof
DOC   drift-tech-writer   Align docs with real behavior
UX    drift-ux-designer   Formalize critical UX constraints
ARC   drift-architect     Protect system boundaries
```

## Role workflows

Use the shortest workflow that gives the agent enough Drift context and proof:

| Workflow | Use when | Roles | Proof |
| --- | --- | --- | --- |
| Start a task | Prompt or scope needs Drift context before implementation. | `$drift-cm` -> `$drift-dev` | `context <file>`, `check --changed` |
| Assess risky change | Contract impact, SSOT impact, or safety is uncertain. | `$drift-cm` -> `$drift-analyst` -> `$drift-dev` | `coverage`, `diff --summary`, `explain` when failing |
| Implement under contracts | Target behavior is clear and protected constraints are known. | `$drift-dev` | `diff --summary`, `check --changed`, `proof --git-base <ref>` |
| Update docs safely | README, command docs, diagnostics, or agent docs must match behavior. | `$drift-tech-writer` | Implementation, tests, contracts, and relevant checks reviewed |
| Design critical UX flow | UI states, stable vocabulary, action hierarchy, or accessibility expectations matter. | `$drift-ux-designer` -> `$drift-dev` -> `$drift-tech-writer` | Critical states, stable vocabulary, action hierarchy, `check --changed` |
| Plan architecture or refactor | Packages, imports, ownership, runtime boundaries, or public APIs may shift. | `$drift-architect` -> `$drift-analyst` -> `$drift-dev` | Boundaries, contract candidates, `coverage`, `check` |
| Adopt DriftLock in existing codebase | A living codebase needs gradual protection without a big bang. | `$drift-cm` -> `$drift-analyst` -> `$drift-architect` -> `$drift-dev` | `coverage`, missing contracts, staged adoption plan |

Each installed role also includes `references/examples.md` with one greenfield
and one brownfield example for that role.

`skills install` prints one installed destination per skill:

```txt
Installed drift-dev -> /repo/.agents/skills/drift-dev
```

Provider output layouts:

| Provider | Destination |
| --- | --- |
| `openai` | `.agents/skills/<skill>/` |
| `claude` | `.claude/skills/<skill>/` |
| `cursor` | `.cursor/rules/<skill>.mdc` |

The installer replaces `{{DRIFT_COMMAND}}` placeholders in bundled text files
with the `--drift-command` value.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Skills were listed or installed. |
| `1` | The provider is unsupported, a requested skill is unknown, the Drift command is empty, a destination exists without `--force`, or files could not be written. |
