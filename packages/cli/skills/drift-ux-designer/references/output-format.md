# UX Contract Brief Output

Use this shape by default:

```txt
Critical states:
- <state and expected behavior>

Stable vocabulary:
- <label, phrase, or term>

Action hierarchy:
- <primary / secondary / destructive action order>

Accessibility expectations:
- <expectation or "none identified">

Suggested contracts:
- <file or behavior to protect>

Non-contract preferences:
- <preference that should remain flexible>

Recommended next role:
- <$drift-dev / $drift-tech-writer / $drift-analyst / clarification>
```

Keep the brief concrete enough for implementation. If a UX requirement cannot be verified or reviewed, mark it as a preference or open decision.
